# 모듈 1개 작업 템플릿 — Codex에 매번 붙여넣기

이번 작업은 SilverRingo D파트 **`M__` 하나만** 구현한다. 작업 전 `git status`, 현재 브랜치, 기존 변경사항을 확인하라.

작업 문서:
- `silver-ringo-d/AGENTS.md`
- `silver-ringo-d/docs/00_MASTER_PLAN.md`
- `silver-ringo-d/docs/01_DATA_CONTRACT.md`
- 해당 모듈 문서 **`silver-ringo-d/docs/modules/M__*.md`** (이번 턴에서 딱 1개)
- 필요 시 `02_API_INTEGRATION.md`, `03_SOURCE_CATALOG.md`, `04_TEST_PLAN.md`만 발췌.

실행 규칙:
1. 먼저 현재 저장소 소스와 명세의 차이, 수정할 파일 및 테스트 계획을 5~10줄로 보고하라.
2. **지정 모듈에 필요한 최소 범위만 구현**하고 다른 모듈을 미리 작성하지 마라.
3. 타 팀 브랜치의 자료는 읽기 전용으로 확인; `ydy_workspace`의 사용자 수정사항 보존.
4. 본문에 없는 결정이 필요하면 가장 안전한 기본값을 택해 문서화. 특히 기능 지원 여부/데이터 근거가 부족하면 임의로 구현 완료로 꾸미지 말고 보고하라.
5. 신규 코드에는 실제 함수 호출 테스트를 작성하고 해당 모듈의 수락 기준을 검증하라.
6. 기존 CI 파일·다른 사람 파일은 허가 없이 변경하지 않는다. commit/push도 하지 않는다.
7. 종료 보고: 변경 파일 / 테스트 명령+실제 결과 / 지식·API 계약 차이 / 부족한 데이터 / 다음 Mxx에 전달할 사항.

이 요청을 **계획 + 한 모듈 구현 + 테스트 + 보고**라는 하나의 작업으로 처리하라.
