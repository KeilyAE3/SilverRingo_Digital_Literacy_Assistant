# 지식 표본 부족 및 아이디어 자료 운영 정책

## 관찰
- 현재 A의 메뉴·버튼은 있으나 상세 화면 이동이 미통합 상태다.
- 현재 C의 학습 코스는 키오스크 1개(6레벨)다. 일상적인 표현의 다양성은 아직 실제 사용자 발화로 측정되지 않았다.
- B는 똑닥 단일 서비스 중심이다. 코드에 들어 있는 Web/Native 단계는 서로 개수가 다르다.

이 표본만으로 정상 작동하는 로컬 Retriever와 Gemini 연동 **프로토타입**을 만들 수 있다. 하지만 폭넓은 생활 서비스 지원 및 의미 검색의 일반화 정확도를 주장할 수는 없다.

## 데이터를 확장할 때의 의사결정
1. `retrieval_cases.json`에 실패한 실질적인 질문을 등록한다.
2. 실패가 alias/키워드 부족인지, 콘텐츠 내용 자체의 부족인지, 미구현 기능 요청인지 분류한다.
3. 표현만 다른 경우 출처가 있는 기존 레코드에 `aliases`를 **D가 정제한 유의어**로 추가한다.
4. 실제 교육 콘텐츠가 없는 경우 사용자에게 부족한 기능과 예시를 보고한다.
5. 팀원이 아이디어를 승인하면 `status=idea`, `source.kind=design_doc`, `related_action_ids=[]`, action_catalog 등록 없음 상태로만 추가한다.
6. 아이디어의 검색은 **미래 계획을 묻는 질의**로만 허용하고 '현재 할 수 있다'는 답변 및 실행 액션은 금지한다.
7. 과거 폐기/지원 중단 자료(`retired`)는 사용자 승인 없이 `idea` 또는 `implemented`로 재분류하지 않는다.

## B 기록 예시
- 현재: 똑닥 병원 접수 (코드 확인).
- 과거 후보: 카카오톡/네이버 전자증명서 (`idea`, 근거는 design 문서).
- 폐기 또는 현재 제외: 정부24, 카카오T (`retired`; 실제 지원을 재개할 때 B와 재확인 필요).
- 코레일도 과거 문서에 구현 기록/아이디어가 있으나 현 지원 목록에선 제외. '미확인' 또는 `retired`로 취급하고 재검증.

## 상태 승격 체크리스트
`idea` → `prototype`은 담당 팀원의 구현물/문서와 테스트 확인 필요. `prototype` → 실제 앱 실행 가능한 액션은 A와 연결점·콜백·권한·테스트 증거가 있어야 한다. RAG에서 설명 가능한 것과 실행 가능한 것은 독립적으로 평가한다.
