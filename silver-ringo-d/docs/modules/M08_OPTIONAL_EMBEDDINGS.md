# M08 (선택) — 임베딩 유사도 Retriever

## 실행 여부 판단
M02의 고정 평가 질문과 수집한 실제 사용자 발화에서 반복적인 검색 실패가 발생한 경우에만 M08을 실행한다. 작은 데이터 수(코스1/레벨6/B 단일 서비스)만으로 임베딩의 의미 있는 우월성을 판단하기는 어렵다.

## 오해 방지
- 생성형 에이전트가 단어 유사성에 관한 목록을 써 주는 것과 **진짜 수치 벡터 임베딩**을 생성하는 것은 다르다.
- 표준 벡터를 만들려면 동일 임베딩 모델로 문서와 질문을 변환해야 한다. LLM이 추측한 임의 좌표를 의미 임베딩이라 주장하지 않는다.

## 설계
- `EmbeddingRetriever`는 `Retriever` 프로토콜을 만족, 기존 키워드 검색을 대체/보완.
- 문서 임베딩은 모델명·차원·문서 내용 hash를 키로 사전 계산, 로컬 `generated/embeddings.json`에 캐시(지식의 단일 원본이 아님).
- 질문 임베딩은 검색 시 해당 모델로 생성, cosine similarity로 상위 K 선택. 문서/질의 task_type 등 공식 API 권장값 확인.
- API 키 없이도 M02로 fallback. 임베딩 재생성은 비용/호출 제한을 보고 승인 후 시행.
- 사용 모델 `gemini-embedding-001` 또는 현재 공식 지원 모델을 확인; 차원 축소 때 normalization 정책 주의.
- Google API 비밀키는 서버만. 원시 사용자 입력을 임베딩 API로 전달하는 개인정보 정책 필요.

## 수락 조건
- M02와 동일한 fixture에서 비교 결과 제출: recall@4, 오검출/금지 hit, 호출 수/비용/지연.
- 개선이 불분명하면 기본 검색은 lexical로 유지.
- 임베딩 호출은 mock으로 테스트하고, 실 API 호출 여부는 명시.

참조: https://ai.google.dev/gemini-api/docs/embeddings
