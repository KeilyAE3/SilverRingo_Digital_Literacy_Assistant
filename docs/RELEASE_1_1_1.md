# Silver Ringo 1.1.1 — main 반영 기록 (2026-10-30)

## 반영 범위

기존 main 2e8f75e의 단일 Android 앱을 기준으로 완성된 2차 통합본을 반영한다. main 1.0.0/code 1에서 1.1.1/code 3으로 높아져 기존 설정을 유지했다. applicationId·Kotlin·Compose·Gradle·SDK 등 런타임 기술 스택은 바꾸지 않았다. API37 호환성 때문에 테스트 전용 AndroidX Test/Espresso만 수정했다.

가이드는 인증·가입·PASS 화면을 잘못 안내하는 것을 막고 스크롤 후 강조 위치를 추적하도록 최신 Juno 서비스/XML을 반영했다. 기존 접근성·오버레이·권한·홈 복귀 구조를 보존했다. 마이크로러닝은 기존 키오스크 콘텐츠·WebView·결과 승인·진도 저장·학습 자산 복사 구조를 그대로 사용한다.

홈 입력·메뉴에서 실제 채팅 화면으로 이동하고 홈/뒤로가기로 돌아온다. Python FastAPI와 Gemini 어댑터·환경변수 설정은 그대로 두고 Android에 POST /v1/chat 클라이언트·최근 대화·응답 표시·쉬운 실패 안내·재시도를 연결했다. 사용자 주소 입력은 제거했고 debug/release 주소는 CHAT_DEV_BASE_URL/CHAT_PROD_BASE_URL로 분리했다. 두 기본값은 비어 있으며 운영 주소가 없으면 '챗봇 서비스 준비 중'이다. API 키는 앱에 없다.

이번 fetch에서 main은 기준과 같아 추가 팀 변경을 덮어쓰는 병합이 필요하지 않았다. jib에 새 스마트폰 1주차 커밋 5c7224c가 있지만 이번 완성된 통합본에는 넣지 않았다. 이 기능은 담당자와 후속 통합·검증해야 하며 다른 원격 브랜치는 수정하지 않는다.

첫 기기 검사는 연결된 기기 없음으로 실패한 뒤 기존 AVD를 시작해 통과했다. 격리 환경에서 FastAPI TestClient가 대기한 실행은 중단하고 일반 실행 환경에서 전체 검사를 다시 완료했다. 테스트를 통과시키기 위한 항목 삭제/비활성화는 없다. 개발 주소 자동 HTTP 연결은 앞선 로컬 검수에서 확인했으며 이번 기본 APK에는 개발/운영 주소가 모두 비어 있다.

커밋 후 최신 origin/main과 안전하게 통합한 뒤 Android·Team Sync를 다시 검사하고 main에만 push한다. GitHub Actions/Discord의 실제 결과는 해당 커밋의 Actions 실행에서 확인한다. APK·키·.env·로컬 설정·캐시는 올리지 않는다.

## 남은 문제와 DHub 승인 후 작업

DHub 승인 전에는 VM을 생성하거나 배포하지 않는다. 실제 Gemini 호출, 교수님 HTTPS 서버, 외부 앱 인증·TTS 실기기 동작은 검증하지 않았다. 운영 URL이 없으므로 현재 배포 기본 앱은 챗봇 준비 중 상태가 정상이다. 서버 인증 계약과 공개 서비스의 이용 제한은 배포 전에 합의해야 한다.

승인 후 VM 생성 → Python 3.12+/기존 api,gemini 설치와 지식 배치 → 서버 환경변수 주입 → FastAPI 상시 실행 → HTTPS·방화벽·접근 정책 설정 → /health와 POST /v1/chat 실기기 검증 → CHAT_PROD_BASE_URL로 release 재빌드·서명 순으로 진행한다. .env는 기본 실행에서 자동 로딩되지 않으므로 실행 서비스에 환경을 전달한다. 자세한 절차는 [챗봇 배포 기준](CHATBOT_DEPLOYMENT.md)을 따른다.

실제 변경 파일은 [파일 변경 기록](ANDROID_FILE_CHANGES.md)에 별도로 정리했다. 학습 추가·화면 연결·HTTP 계약 기준은 [2차 통합 기준](ANDROID_INTEGRATION_V2.md)을 따른다.
