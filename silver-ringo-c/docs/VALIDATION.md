# 실행 검증 결과

검증일: 2026-10-24. 소스 제공, 브라우저 실행 검증, Android 실기기 검증을 구분한다.

## 통과한 검증

**Node.js 순수 주문 엔진 테스트: 11/11 통과.**

- 지정된 전체 주문과 영수증/7,500원 합계
- 단품 5,000원, 세트 옵션을 단품에 적용하지 않음
- 치즈스틱 추가금과 수량별 계산
- 빈 장바구니의 주문 확인/결제 차단
- 다중 상품 추가/삭제와 합계
- 잘못된 장소·결제 방식에 대한 실패 판정
- 이전 화면 복귀 후 수량 수정 및 상태 유지
- 1~5 단계 각각의 부분 학습 완료
- 수량 1~9 제한, 잘못된 액션 및 결제 중복 실행 거부
- reducer 입력 상태를 변경하지 않음
- 이전 레벨 통과에 따른 해제, 자유 실습의 잠금 해제 제외

**실제 Chromium 153 headless + Playwright 1.62.1 상호작용 검증 통과.**

브라우저 기본 다운로드 경로가 차단되어 테스트 환경에 별도로 준비한 Chromium 실행 파일을 사용했다. 사용자 앱의 런타임 의존성은 아니다. 테스트 스크립트는 기본 Playwright Chromium 또는 `SR_BROWSER_PATH` 환경변수의 실행 파일을 사용할 수 있다.

- 원본 v2: 단품 선택 후 사이드/음료를 거치며 7,500원으로 표시되는 오류를 브라우저에서 재현했다.
- 새 버전: 1~6단계 각각 목표대로 수행하고 완료/다음 단계 해제를 확인했다.
- 새로고침 후 완료 레벨을 유지했다.
- 실전/자유 실습 화면에 정답 강조가 없는 것을 확인했다.
- 다중 상품/치즈스틱 추가금/수량/삭제/뒤로 가기/진행 중 세션 재개를 조작해 확인했다.
- 잘못된 주문을 완료하면 재시도 피드백을 표시했다.
- 단품에서 사이드 선택이 사라지고 5,000원으로 표시됐다.
- 빈 장바구니에서 주문 확인 버튼이 제거됐다.
- 390px·320px 및 320px에서 기본 글꼴을 20→30px로 확대한 메뉴 화면에 가로 넘침이 없었다. 모든 화면의 200% 확대나 TalkBack 인증을 의미하지 않는다.
- embedded 진입/완료 JSON/목록 복귀 메시지를 브라우저 모의 객체로 확인했다. Android 기기 브리지 검증과는 다르다.
- 분리 소스 화면과 단일 HTML 데모에서 주문 시작부터 결과 확인까지 실행했다. 데모의 인라인 SVG 로딩도 확인했다.
- localStorage 접근을 차단해도 안내를 표시하고 현재 실습이 계속 진행됐다.
- 학습 목록·키오스크 메뉴·옵션 패널·390px 모바일 화면을 렌더링해 한국어 표시와 레이아웃을 육안 확인했다.
- 메인 테스트 페이지에 자바스크립트 pageerror가 없었다.

`browser-test.log`에 테스트 출력이 있다. 브라우저 테스트 이미지는 내부 QA용이며 전달 ZIP에 포함하지 않았다.

## Android 검증 한계

- JDK 17 존재, Gradle Wrapper 스크립트와 JAR 포함 여부 확인.
- `./gradlew :app:assembleDebug --no-daemon`을 실제 시도했으나 **Gradle 배포본 다운로드에서 Network is unreachable 오류**로 중단됐다. Android SDK도 이 환경에 준비되어 있지 않다.
- 따라서 Gradle 의존성 해결·Kotlin 컴파일·APK 설치·Android WebView 렌더링·음성 출력·기기 뒤로가기·화면 회전·TalkBack은 **미검증**이다. APK를 포함하지 않는다.
- Android 코드는 소스 검토와 브라우저의 메시지 계약 모의 검증까지만 완료했다. 최종 네이티브 Compose 키오스크 실습 화면은 아직 구현하지 않았다.
- 브라우저 TTS 호출 코드가 있어도 실제 한국어 음성 출력과 이해도는 별도 기기에서 확인해야 한다.

## 다음 검증 우선순위

1. 인터넷과 SDK가 있는 Android Studio에서 빌드/설치. 오류가 발생하면 실제 Gradle 로그를 기준으로 수정.
2. 한국어 TTS 음성 설치/미설치, WebView 버전 지원/미지원, 백그라운드 이동 시 발화 중지 확인.
3. Android 레벨 완료 → 목록 복귀 → 다음 레벨 해제 및 앱 재실행 후 유지 확인.
4. TalkBack 읽기 순서, 버튼 이름, 시스템 큰 글꼴, 작은 기기에서 옵션·장바구니·결제 화면 확인.
5. 화면 회전·프로세스 종료 후 진행 중 실습의 정밀 복원 추가 여부 결정. 현재 완료 진도는 저장하지만 Android 실습 화면의 정밀 복원은 제공하지 않는다.
6. 실제 고령 사용자 관찰. 메뉴 그림 식별, 단품/세트 문구 이해, 두 영역 스크롤 부담 확인.
7. 위 결과를 반영한 뒤 전면 Compose 실습 UI 전환 범위를 합의.
